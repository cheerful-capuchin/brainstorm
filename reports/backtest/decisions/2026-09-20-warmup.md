# Decision: Remove the warmup historical replayer from the backtest path

Date: 2026-09-20
Scope: `structure-strat-template-core`, `--regime backtest`
Related: `brainstorm/reports/backtest/2026-09-20-hist-replay.md`

## Context

- The Databento historical integration replaces the Arrow file readers. Every place that
  constructs a historical provider has to be taught about Databento; the warmup replayer is a
  second such place.
- The strategy currently declares no warmup periods. `NodeExtension::warm_up_period()` defaults to
  `None` (`dsl-runtime/crates/dsl-runtime-nodes/src/lib.rs:103`) and the generated `NodeRepo` sets
  no periods, so `calculate_lookback_window_ns` returns `0` (`generated/mod.rs:31`).
- With a zero lookback, `create_warmup_hist_replayer_backtest` early-returns an empty replayer
  (`helpers.rs:177-180`): no streams, one `ReplayComplete`, then exit. The warmup replay carries no
  data today; it is pure scaffolding.
- The backtest path is slated for a rewrite anyway. The goal now is to minimize the work to get
  Databento feeds working, without committing to the larger FSM rewrite.

## Decision

Remove the warmup historical replayer from the **backtest** wiring, and keep the strategy FSM
unchanged. The strategy still starts in `Warmup` and still transitions to `Backtest` on the first
`ReplayComplete`; that signal is now emitted by the mux thread directly instead of by a drained
warmup replayer.

Concretely: the mux sends one `ReplayComplete` (the warmup transition), then forwards the backtest
channel, then sends the final `ReplayComplete` (the backtest transition to shutdown). The
`Warmup` state, `StratWarmupState`, and `StratBacktestState::from_warmup` all stay.

Live regime is untouched.

## Change list

### Delete

- `helpers.rs:161-269` — `create_warmup_hist_replayer_backtest` (~109 lines). It is the only
  Arrow-dependent warmup constructor on the backtest path.
- `helpers.rs` imports that become unused on this path (`ArrowFileProvider` stays: the backtest
  replayer still uses it; `warehouse` stays for the backtest replayer).

### Edit `structure-strat-template-core/src/lib.rs`

- `prepare_backtest_component_params` (512-562): stop computing `warmup_lookback_window_ns` and
  drop it from the return tuple. `calculate_lookback_window_ns` stays (live still uses it).
- `setup_backtest_historical_replayers` (593-674): remove the warmup channel pair, the
  `create_warmup_hist_replayer_backtest` call, and the `warmup_lookback_window_ns` argument. Return
  `(BacktestHistReplayerSetup, backtest_hist_sync_rx, backtest_hist_async_tx)`.
- `start_backtest_components` (724-773): drop the warmup replayer parameter, its `start`, and its
  handle; return only the backtest handle.
- `shutdown_backtest` (784-879): drop `warmup_replayer_handle` and its `join` /
  `join_stream_handles` sites.
- Mux thread (1196-1281): collapse Phase 1. Drop the `warmup_hist_sync_rx` loop and the
  "warmup done" log; keep a single `send_replay_complete(&fwd_tx)` before entering the main-phase
  loop. Phase 2 and its replayer-`ReplayComplete` filter are unchanged.
- `run_strategy_backtest` glue: update the destructuring at 1122-1136, the `start_backtest_components`
  call at 1325-1329, and the `shutdown_backtest` call at 1358-1365.
- `build_backtest_engine_params` (682-715): unchanged — `expected_replay_completion` stays
  `WarmupReplay`, because the FSM still starts in `Warmup`.

### Unchanged (deliberately)

- `StratLogicState::Warmup`, `state/strat_logic/warmup_state.rs`, and the `WarmupReplay` /
  `BacktestReplay` branches in `strat_logic.rs:128-247`.
- `StratBacktestState::from_warmup` (`btest_state.rs:86-142`), including the
  `mkt_data_stream_statuses` seeding and `apply_starting_positions`.
- The whole live path: `create_warmup_hist_replayer_for_live_regime`,
  `setup_live_historical_replayer`, `build_live_engine_params`.

## Invariants to preserve

- **One `ReplayComplete` per phase, in order.** The strategy consumes
  `expected_replay_completion` on each `ReplayComplete` (`strat_logic.rs:141-145`). If the mux emits
  the warmup signal and the final signal, the FSM walks `Warmup → Backtest → shutdown` exactly as
  today. Dropping a signal while leaving `expected = WarmupReplay` stalls the strategy silently.
- **The mux still filters the replayer's own `ReplayComplete`.** The backtest replayer emits one
  (`hist_data.rs:833`); the mux must keep discarding it and send the authoritative one, or the
  engine panics on duplicates.
- **`mkt_data_stream_statuses` is still seeded.** It is populated only in `from_warmup`. Since
  `from_warmup` still runs (on the mux-emitted warmup `ReplayComplete`), the end-of-replay
  `all_streams_exhausted` path still fires.

## Alternatives considered

- **Gut the constructor only (keep the idle replayer thread).** ~100 lines deleted, zero ripple.
  Rejected: leaves the thread, the mux phase, and the plumbing in place; Option 1 is the same
  provider-count win with the scaffolding gone.
- **Start directly in `Backtest` (delete the `Warmup` state).** Cleaner end state, but requires a
  new `StratBacktestState::new`, a regime branch in `component.rs::create`, and
  `expected_replay_completion = BacktestReplay`, plus re-seeding `mkt_data_stream_statuses`.
  Deferred to the backtest rewrite.

## Consequences

- The Databento historical provider has exactly one construction site on the backtest path:
  `create_backtest_hist_replayer`.
- One fewer replayer thread, one fewer mux phase, and one fewer place to keep in sync when the
  backtest is rewritten.
- The FSM keeps a `Warmup` state that is now always entered with an empty history. That is already
  the case today; it becomes visible and can be removed in the rewrite.
- Warmup for the live regime is unaffected, so live behavior does not change.
