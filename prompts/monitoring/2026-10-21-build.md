how would you build the build id integration?

I imagine we need some kind of a clear pipeline.
I was thinking of building something like Platform API (see: heimdall/README.md).
Where the whole pipeline is this function.

That's how we can enforce locally that all steps are followed.

The `build` is a combination of many things:
- git
- image
- toolchain
- binaries
- linker
- monitoring registry
- debug info registry
- etc.

Therefore, I was thinking of having it built as event-sourcing pipeline.
I imagine we can use the application server for the most of it, and have a fallback to a bucket in case the application server has an
issue for some reason. Then, once the app server is deployed, there is a job to pull all those build ids into the database.
So, the primary way is the application server and the bucket is a redundancy in case the app server doesn't work for some reason.
We store the apache avro schemas that describe the events in the database and in the bucket.
Then each step in the build pipeline is an event that is encoded using the schema and is sent to the application server.
Application server stores this stream of events in the database and has a materialized record for the build.
The monitoring registry file with all the events the process is going to emit are going to be stored in a bucket and the event
will include the reference to it.
The debug info, I assume, is the same.
Because each step is an event, we can record the latency of the steps.

So, I guess, the first command we send is create build, then we just add events with that build id and maybe some orderand

this build id is embedded in each binary and is used for monitoring and tracking of each code piece.

I imagine all the endpoints are internal with the requirements of the participants to be in the structure org.
Application server assigns the snowflake id. If we cannot reach the app server, we create some kind of u64 id with timestamp and randomness.

so, the "CI" is

```ts
function* build_pipeline(p: Platform.Trait) {
    let build = yield* p.structure().builds.create({
        create_time: p.timers().now(),
    });

    let image = yield* p.docker().build({
        // ...
    });
    yield* p.structure().builds.attach_git({ build_id: build.id, git: { sha: image.labels.git_revision } });
    yield* p.structure().builds.attach_image({ build_id: build.id, image: { digest: image.digest, tag: image.tag } });
    // ...

    yield* p.structure().builds.commit({ build_id: build.id });
}
```

I'm not fully sure about the API and how do we manage the docker bake. Maybe we don't, but that's the general idea.
